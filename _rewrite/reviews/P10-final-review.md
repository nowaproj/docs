## Notes for the layout.md row

1. Where the button lives: `BFGroup.build` (`packages/designer/lib/src/details/group_details.dart:72-124`) builds the header as `Row(Text('Group'), Row(WidgetMoreButton(actions: [Replace with...]), 8 px gap, Stack button, right-arrow button, down-arrow button))`. The ⋯ is the first child of the button row, so it sits to the left of the three buttons. The three buttons are the stack icon, the right arrow (`_toDirection(horizontal)`) and the down arrow (`_toDirection(vertical)`): matches the page.
2. When it shows: `WidgetMoreButton.shouldShow` is `HoverZone.of(context) && _entries(context).isNotEmpty` (`packages/core/lib/src/fields/class_field.dart:403-405`). The entries are never empty here because `actions` always holds **Replace with...**, so hover is the only condition. The hover zone is the whole **Group** section: the section is built by `FieldBuilder`, which wraps it in `AutoHoverZone` (`block_field.dart:857-859`; base widget path `widget_details.dart` `BFBaseWidget` to `FieldBuilder`). So "while you point at the section" is right. The icon is `Icons.more_horiz_outlined` (`nowa_widgets.dart:160-161`); the shipped screenshot `design-layout-1.png` shows no ⋯ because the pointer was elsewhere.
3. Entries (`class_field.dart:396-401`), in order: "Open in new tab" (only for a class declared in project source, `openInFileEntries`), one entry per public constructor (only when the class has two or more, `constructorMenuEntries`), the group's own action **Replace with...** (opens the widget picker dialog, swaps the group via `recordReplaceAndKeepArgs`), and **Remove** (`isRemovable`). **Stack**, **Row** and **Column** are library classes (`ClassDeclInternal` with one constructor each, `packages/core/lib/src/interpreter/libraries/material_library.dart`, `$Stack` at L76829), not `ClassDeclImpl` classes with a source file, so the first two never show for them. (`NFlex` from `nowa_runtime`, used by some templates, also gets the **Group** section; I did not check its entries and the page does not mention it.)
4. When **Remove** shows: `isRemovable` is `instance.widgets.length > 1`, or `> 2` when the instance's top block is a layout wrapper (`Expanded`, `Positioned`, `SizedBox`, `FlexSizedBox`, `BoardPosition`; `widget_blocks.dart:465`). `instance.widgets` is the group plus every wrapper above it (`designer_model.dart:225-242`). So a bare group, or a group that has only a position or size wrapper, has no **Remove**; a group with another wrapper does. The usual one is the **Padding** wrapper that the Group section's **Padding** field adds (`inline_wrapper_fields.dart:17-37`, `recordAddWrapper`).
5. What **Remove** does on a group (not on the page, code only, not seen live): `_remove` calls `recordRemoveWidget(field.block)` on the group block itself, so it dissolves the group and keeps its wrappers (`designer_model.dart:394-417`, `widget_blocks.dart:131-162`). When the group's parent is not a list (for example the **Padding** wrapper), `dissolveTree` sets only `children.first` into the parent's slot, so a group with several children keeps only its first child. The undo record exists. I left the effect off the page; worth one live check and, if confirmed, an entry in `product-issues.md`.
