### Use Keys conclusion (the high-risk claim)

- **Official source found.** Supabase changelog entry 42949 (17 Feb 2026) and its GitHub discussion: the Data API root `https://[projectref].supabase.co/rest/v1/` (the OpenAPI spec, which lists tables, columns and types) stops answering the `anon` key. Timeline: newly created projects from **11 March 2026**, **all existing projects from 8 April 2026** (hosted; self-hosted from the week of 6 July 2026 per a staff comment of 18 June). It keeps working with the `service_role` key or the new secret keys; normal data access (`/rest/v1/your_table`) is unaffected. The error body is `{"message":"Access to schema is forbidden","hint":"Accessing the schema via the Data API is only allowed using a secret API key."}`. Supabase wrote "We may push these dates back ... but we will not move them forward"; neither the changelog nor the discussion confirms afterwards that 8 April happened as planned, and nothing says it was postponed. Third-party corroboration (not official): WeWeb's staff said on 12 March 2026 their editor fetched the schema with the anon key and moved to the `service_role` key; a FlutterFlow community post from about 12 March reports new projects already refused.
- **What Nowa's Use Keys path calls.** **Use Keys** → `SupabaseManager.connect` fires `getTables` with the pasted anon key at once (`supabase_manager.dart:84`, not awaited, error unhandled). **Tables**, **Fetch Tables** and Set up all go through `refreshTables` (`supabase_manager.dart:113-140`; callers `ui/sb_tables_page.dart:31`, `templates/ui/template_category_view.dart:64`, `templates/ui/table_selection_view.dart:48`, `migrations/sb_backend_bundle_service.dart:244`), which uses the anon key unless the Nowa project is authorized (`isOAuthAuthenticated`, `supabase_oauth_service.dart:100-111`), in which case it fetches the `service_role` key through Nowa's Management API proxy (`supabase_oauth_service.dart:84-98`) and uses that. `fetchTables` calls `GET $url/rest/v1/` and throws `Problem with fetching tables: <message>` when the answer has no `info` (`supabase_service.dart:48-63`). On the Tables page that shows as "Error fetching tables: Exception: Problem with fetching tables: Access to schema is forbidden"; in Query Templates the exception isn't caught (`template_category_view.dart:57-68`), so **No Tables Found** simply stays.
- **Verdict.** The claim is kept, worded only as far as the sources go: Supabase *announced* the change from April 2026, and the list *may not load* with keys alone; the fix (authorize once with **Connect**, then **Select** the same project) follows from the code. Not seen live in Nowa with a Use Keys connection (the phase 13 table loads were all in authorized projects, so they don't tell either way; the writer's "live corroboration" from `captures/phase13/a.md:72` is explained by tables not being loaded when a project opens, `supabase_manager.dart:169-186`). Same hedge applied in database.md step 2. The writer's proposed known-issues entry for B12 ("Since April 2026, Supabase no longer gives the table list to the anon key ...", in `P14-B10-notes.md` "For other pages") should get the same hedge before the orchestrator forwards it.
