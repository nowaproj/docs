## New developer facts proposed for #publishing (not moved from a page)

- Cloud builds run the workflows in the project's `codemagic.yaml`: `android-debug-workflow` (`flutter build apk --debug`, artifact `build/**/outputs/flutter-apk/*.apk`), `android-workflow` (release `appbundle` and `apk` signed with the `android_key_info` group: `CM_KEYSTORE` base64, `CM_KEYSTORE_PASSWORD`, `CM_KEY_ALIAS`, `CM_KEY_PASSWORD`), `web-workflow` (`flutter build web --release`, zipped) and `ios-workflow` (group `ios_credentials`). **Reset to default** on the file's error bar in code mode rewrites the default content. Evidence: `packages/core/lib/src/file_system/codemagic_file.dart:1-125`, `packages/core/lib/src/widgets/code_editor/nowa_code_editor.dart:273-292`.
- iOS signing step: `keychain initialize`, `app-store-connect fetch-signing-files "$BUNDLE_ID" --type IOS_APP_STORE --create`, `keychain add-certificates`, `xcode-project use-profiles`; upload through `publishing: app_store_connect` with the API key. `$BUNDLE_ID` is the **Bundle Identifier** saved with the App Store Connect credentials, and `CERTIFICATE_PRIVATE_KEY` is the distribution certificate key. Evidence: `codemagic_file.dart:84-124`, `packages/core/lib/src/cloud_build_v2/ui/workflow_manager.dart:485-520,683-712`.
- **Certificate Private Key** must be the certificate's RSA private key as PEM text (`-----BEGIN RSA PRIVATE KEY-----`), not a binary PKCS#12 file: Nowa decodes the picked file as strict UTF-8 (`packages/core/lib/src/file_system/encoding.dart:8-10`, `workflow_manager.dart:418-440`), and the picker only lists `.p12` (`packages/core/lib/src/cloud_build_v2/ui/ios_details.dart:151-156`). To reuse a certificate made on a Mac: export it from Keychain Access as `.p12` with no password, run `openssl pkcs12 -in IOS_DISTRIBUTION.p12 -nodes -nocerts | openssl rsa -out ios_distribution_private_key`, then give the text file a `.p12` extension so the picker shows it (Codemagic's steps for the same variable: https://docs.codemagic.io/yaml-code-signing/alternative-code-signing-methods/). Nowa's own **Download Certificate** file is already in this format (`workflow_manager.dart:442-464`). Product issue P16.
- The iOS `Info.plist` template doesn't set `ITSAppUsesNonExemptEncryption` (`packages/core/lib/src/file_system/templates/ios/info_plist_template.dart`), so App Store Connect asks the export compliance questions for each build. People who code can add the key (Apple: "specifying encryption settings in the app's Info.plist file ... eliminates the need to answer encryption questions with each app submission", https://developer.apple.com/help/app-store-connect/test-a-beta-version/provide-export-compliance-information-for-beta-builds/).
- iOS app icons keep their transparency: Nowa calls the icon generator without `remove_alpha_ios` (`packages/core/lib/src/settings/app_icon_manager.dart:105-142`; default false in `packages/launcher_icon/lib/src/config/config.dart:25`; the generator warns "Icons with alpha channel are not allowed in the Apple App Store", `packages/launcher_icon/lib/src/ios.dart:77-80`).
- **Build version** and **Build number** are the pubspec `version` (`x.y.z+n`), which Flutter passes to `CFBundleShortVersionString` / `CFBundleVersion` (`info_plist_template.dart:31-36`) and `versionName` / `versionCode` (`packages/core/lib/src/file_system/templates/android/app_build_gradle_template.dart:67-68`); settings at `packages/core/lib/src/settings/project_detail_settings.dart:286-330`.
- (new, added by verifier P14-B11-V) With `--create`, the iOS signing step registers a missing bundle ID itself (`Did not find ... with identifier` is raised only without `--create`), and when no Apple Distribution certificate matches `CERTIFICATE_PRIVATE_KEY` it creates one from that key, which is where Apple's certificate limit bites. Evidence: codemagic-cli-tools `src/codemagic/tools/app_store_connect/actions/fetch_signing_files_action.py:114-163`; Nowa's script `packages/core/lib/src/file_system/codemagic_file.dart:98-106`.
