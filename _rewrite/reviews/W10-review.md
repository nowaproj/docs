## Open issues

Product behaviour to confirm or report (the docs follow the code as it is today):

1. **Revert Commit** (git.md): in local projects it stages the undone changes and creates no commit, yet the confirmation says "This will create a new commit that undoes the changes made in the selected commit." and the snackbar says "Commit reverted successfully." Cloud revert is a server call (`POST /git/revert/<sha>`, `network_git_service.dart:282-286`), not readable here, so the page states only the local result. Needs a product decision or a cloud check.
2. **Local / Remote panes** (git.md): after **Bring my changes** the labels are the reverse of what they suggest (local projects, tested). For cloud projects conflicts come from the server API (`network_git_service.dart:221-225,236-239`); which pane is which is unknown. The page documents the local swap only.
3. **Accept closes every conflict** (git.md, from reading only, not run end to end): after the first **Accept Local** / **Accept Remote**, `resolveAllConflicts()` clears all conflict entries and the **Conflicts** list (`git_manager.dart:731-734`, `local/local_git_service.dart:368-372`). If the window is closed part-way, the remaining files would keep their merge markers on disk and no longer be listed. The page says "Repeat for each file".
4. **Identity errors in local projects** (git.md, github.md): the identity form is raised only for a server error on commit and for the text "failed to build signature from config" (pull, merge), which the bundled libgit2 never produces ("config value 'user.name' was not found"). Local commit, pull or merge without an identity shows a raw error. The pages say the form is for cloud projects and tell local users to set an identity first.
5. **"You need to provide authentication for this action" popup** (git.md, github.md; writer open question 2): its form is the **Legacy Remote Credentials** one, even in a local project, and it saves the token on Nowa's servers (`locator.get<GitService>()` is `NetworkGitService`), where local Git never looks. The pages send local users to **External Local Credentials**.
6. **Discard deleting new files** (git.md): verified for local projects. The cloud `reset` is a server call, so "deletes files you added since" is unverified there; kept because it errs on the safe side.
7. **Timeout message** (github.md): "Authorization timed out. Please try again." is passed to a callback that only closes the window for GitHub (`github_integration_settings.dart:93-99`). The page describes what the reader sees.
8. **SSH keys** (github.md; research open question): What's New 3.12.0 says "Point Nowa at a key", but the credentials dialog can only create access-token entries and **Add Existing Repository** takes http(s) URLs only. The page documents agent and default keys, and sends SSH remotes to be set up outside Nowa.
9. **Refresh** (git.md): the comment at `git_manager.dart:272-274` says Refresh fetches at once, but `refresh()` calls `tryUpdateState()`, which only fetches when the five-minute interval is due. The page does not claim it.

Not verifiable here (kept and flagged):

The sandbox proxy returns 403 for both hosts and `github/docs` is outside the allowed MCP repositories. Both are the providers' canonical pages; recheck at release time.
11. **Server-side Git** (git.md, import.md): conflict sides, revert, reset, the default branch after **Create Git Repository...** in a cloud project, and `cloneToCloud` run on Nowa's servers; the client code does not show them.
