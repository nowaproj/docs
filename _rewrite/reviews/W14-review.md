## Summary

- Pages checked: 5 (`integrations/index.md`, `show-data.md`, `constants.md`, `rest-api/index.md`, `rest-api/import.md`). All five were verified against the code, the writer notes were used only as a starting point.

- Most serious errors fixed:
  1. `rest-api/index.md` said a new request opens in the bottom panel right after **Create**. It does not: you click the request first (`api_outline.dart:181-215`, `api_provider.dart:37`).

  4. `rest-api/index.md` and `show-data.md` called **API** / **Query** / **Model** "buttons"; they are row labels and the button next to them shows the chosen function (`none` until chosen) or the model name.
  5. `rest-api/index.md`: the **x-www-form-urlencoded** row promised form fields, but the code only gives the JSON editor and the content type.
  6. `index.md`: the **Enabled** switch is missing on the **Google Sign-In** page when Firebase manages it (**Managed by Firebase** instead).
  7. `import.md`: the **Base URL** is not taken "from the description" (OpenAPI `servers`, the pasted address, or a Postman variable); the Postman collection is named from `info.name`, not a title; the cURL base-URL mismatch error was missing from the failure table.
- Verified and left as written: every label in the Api panel, collection dialog, request editor, test view, Generate Models wizard, **Model** menu, import dialog, Xano steps and cURL dialog; Data Builder source names, row labels, **Loading Widget** / **Error Builder** and their defaults; the list of keys on the Constants page (Stripe, RevenueCat and Google Sign-In **Web Client ID** only, Supabase keys under **Custom Constants**, Google Maps, AdMob, Deep Links and the **iOS Client ID** stay on their own pages); the known-issues link and anchor.

One banned filler word ("just") removed. Body word counts after edits: index 513, show-data 754, constants 564, rest-api/index 1198 (trimmed from 1210), import 742.

## Open issues (not resolved)

1. **DOWNLOAD method.** The request method dropdown lists seven methods; the seventh is **DOWNLOAD** (`requests_drop_down.dart:36-42`). The method setter only swaps the Dio call (`request_func.dart:59-62`), and the generator asserts a save path that no field supplies (`request_func.dart:231-236`), so it probably yields `dioClient.download(url)` without Dio's required save path. Not run. The page says "such as GET, POST, PUT, DELETE, PATCH or HEAD" and does not mention DOWNLOAD. Needs a product check.
2. **x-www-form-urlencoded** edits JSON text and saves it as a String body only when it parses as JSON (`api_request_body.dart:40-41`, `json_body.dart:24-33`, `body_type_actions.dart:174-181`). How a real form endpoint receives that is unverified, so the page states only what the code shows. Possible product issue.
3. **Empty Base URL.** Closing any field of the collection settings dialog runs `setBaseUrl(StringBlock(''))` for an empty field (`api_edit_collection_dialog.dart:84-86`). After that, **Import from curl** treats `''` as a matching prefix and keeps only the path (`curl_service.dart:19-21`), so the request loses its host. Read from code, not run. Not documented. Possible product issue.
4. **Request without a model on the board** (Dio `Response` cannot be mocked, so the board may call the real API; `mock.dart:94-225,244-310`): still not described, same as in the writer notes. The page only describes requests that have a **Model**.
5. **Capture placeholders** for rows marked `not-possible` or `skipped: low value` in `captures/requests/W14.md` are still in the pages (`integrations-rest-api-2`, `integrations-constants-1`, `integrations-index-1`). Captured images exist for `integrations-rest-api-1` and `integrations-import-1` (they match the labels in the pages). The embed step should drop the skipped placeholders.
6. `docs/troubleshooting/known-issues.md` is in the W14 batch in pages.md but was not in this task. Only the anchor `#api-requests-blocked-in-the-browser` was checked (line 23, text matches the REST API page).
7. Not verified in a running app (derived from code): the Circuit entry steps in "Call it from logic", the `PACKAGE:MY_APP` category name and **Members**, and the placeholders the board shows for a model (`[title]`, three items).
