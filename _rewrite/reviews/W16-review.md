## Open issues

Product bugs and quirks (the pages state what the code does; suggest adding 1-5 to `product-issues.md`, and 6 after a check in the app):

1. **Failed Connect Apps cannot be retried on the same screen.** `creatingAppsError` is set in every `catch` and never cleared (`packages/data/lib/src/firebase/setup/views/fb_apps.dart:57,211,221,231,234-239`), so `createSetup` is skipped on every later click until the screen is rebuilt. `connect.md` tells users to click the back arrow and pick the project again. If fixed, change it back to "click **Connect Apps** again".
2. **`google_sign_in` 7.x vs the generated `signInWithGoogle()`** (`fb_auth_blocks.dart:109-129`, `fb_auth_manager.dart:66`). Verified against the 7.2.0 package source; a build that reaches `lib/firebase/firebase.dart` with **Google** on fails. Documented in a `:::note` in `auth.md` (version-scoped to 3.12.5; delete it when the template is updated). Dev (`/home/user/nowa`) still has the same template.
3. **Disconnect Project leaves `google_sign_in` installed and does not rewrite `Info.plist`** when the Google or Phone provider was on: `FBManager.disconnect` sets `data.fbBaseClass = null` before `auth.disconnectAuth()`, so `isGoogleAuthEnabled` and the other provider checks are false (`firebase_manager.dart:158-164`, `fb_auth_manager.dart:121-133`). Not mentioned on the page (it says "the Firebase packages").
4. **Turning Authentication (or Email/Password) off leaves `sendPasswordResetEmail()`** in `FirebaseService` (`fb_auth_manager.dart:142-145`). Documented in `auth.md`.
5. **The FCM test turns an expired Google sign-in into a full Firebase disconnect** (`notification_settings.dart:183-186`; the FCM client has no 401 interceptor, unlike `FirebaseApiServiceImpl`). Documented in a `:::warning` in `notifications.md`. Token lifetime is not in code, so the page gives none. Worth confirming with the team; update the page if it changes.
6. **iOS bundle ID is camel-cased per part** when the Firebase iOS app is created and matched (`firebase_api_service.dart:103`, `fb_apps.dart:178`), while Xcode keeps the **Bundle Identifier** unchanged (`packages/core/lib/src/project/rename.dart:117-121`) and default identifiers can contain capitals (`naming.dart:247-251`). Whether this breaks Firebase on iOS cannot be told from code. Pages say only "builds the iOS bundle ID from it". Check in the running app with a project name that has capitals.

Unverified (not stated on the pages, or stated with a hedge):

7. What `verifyPhoneNumber`, `sendVerificationEmail` and `sendPasswordResetEmail` do in **Play** (no preview override, `fb_auth_blocks.dart:326-402`); `auth.md` names only the four functions that open preview dialogs.
8. **Play** reaching the real Firestore (`firestore.md` "Click **Play** ... to see your real documents"): follows from `RunMode.simulate` in `play_mode.dart` and `FirestoreGetter`, the same path as **Run Test**, but was not run end to end. The Windows advice mirrors the in-app overlay.
