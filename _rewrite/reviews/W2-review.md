## Open issues

1. **Attach text file on the web app (context.md).** `PromptController.attachTextFile` keeps only files with a `path` and calls `isProbablyText`, which opens the file with `dart:io` (`packages/ai/lib/src/prompt_controller.dart:221-235`, `packages/core/lib/src/utils.dart:358-375`). A browser gives no file path, so the option probably does nothing on the web app. Not verified at runtime, so the page makes no platform claim. Check in a web capture session; if it fails, add a "desktop app only" note or log it in `product-issues.md`.
2. **External agent plan name (external-agent.md).** The code gate is the account entitlement `external_agent`, with the comment "Granted by the beta plan, which stacks on top of whatever plan the user is on"; the word Enterprise appears only in What's New. The page keeps the **Enterprise** badge and says "an account that has access". Product should confirm that "Enterprise" is the right public name; if not, change the badge and the one sentence in "Before you start".
3. **Reapply semantics (undo-and-history.md).** The interface comment says reapply covers "the clicked checkpoint and all subsequent checkpoints", but the implementation reapplies the clicked one and everything before it (`checkpoints/checkpoint_service.dart:39-40` vs `:276-300`). The page follows the implementation. Worth one runtime check (restore request 2 of 4, reapply 2, then 4). Edge case not on the page: if the same request also saved an image, `pubspec.yaml` is bracketed by that save, so a restore can also roll back a package entry added before it.
4. **Restore dialog wording (undo-and-history.md).** The dialog is titled **Undo Last Request?** and lists only the clicked request's files, although the restore also undoes later requests. The page's warning covers it; the dialog itself may mislead (possible product issue).
5. **Auto-approve placement (connectors.md).** **Auto-approve tools** exists only in the Figma menu (`SupabaseMcpMenu` has no such item), so a Supabase-only user must link Figma to reach it. The page describes this plainly (possible product issue; research open question 2).
6. **Which connector actions need approval (connectors.md).** The server decides which MCP calls raise an approval request; the client waits for every request it receives. The page states the documented behavior (What's New 3.12.3, the Supabase instructions: "All MCP tool calls are reviewed by the user before execution").
7. **Editor Undo vs AI edits.** Whether Ctrl/Cmd + Z or **Action History** also reverts AI edits is not shown by the code reviewed, so no page claims it (research open question 9).
8. **Checkpoints across machines and sync.** Whether checkpoints survive a Cloud/Local sync, a clone or opening the project on another computer is not shown; undo-and-history.md hedges with "where the project still holds them" (research open question 14).
