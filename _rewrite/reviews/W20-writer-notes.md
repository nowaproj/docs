Research answers, with refs:

**Redirect Logic in the Router panel.**
- Two places, same UI: **Router Configuration** (click the gear; nothing selected) has **Initial Location** (must start with `/`, error text 'Initial location must start with a "/"'), **Redirect Logic**, **Remove # in URLs**: `router_block_view.dart:129-140, 388-392, 517-631` (error text `:532-537`). A selected route has **Type** (read-only) and **Redirect Logic**, then the route's own fields: `router_block_view.dart:443-515`.
- Button: **+** with tooltip **Add Redirect Logic** while none exists, then the bolt button with tooltip **Edit Function** (`EditFuncExprButton`, `shell_route_node_view.dart:257-272`). No remove button exists (by absence in `router_block_view.dart:496-498, 611-613`), so the page does not tell users how to remove it.
- What the function is: created as `(BuildContext context, GoRouterState state)` with body `return null;` (`router_block_view.dart:463-471` route, `:551-557` app-wide). Type of the `redirect` argument is `FutureOr<String?> Function(BuildContext, GoRouterState)`: `packages/core/lib/src/interpreter/libraries/go_router_library.dart:3810-3828` (GoRouter constructor, cast at `:3849`), `:1943-1980` (GoRoute constructor), and go_router's own typedef `go_router-17.1.0/lib/src/configuration.dart:20-22`. `GoRouterState` members available to Circuit (`uri`, `matchedLocation`, `name`, `path`, `fullPath`, `pathParameters`, `extra`): `go_router_library.dart:4193-4199`. The page says only "receives `context` and `state` (where the person is heading)" and "returns a path ... or nothing (`null`)".
- The product's own help text for **Redirect Logic** names this use: "For example, you might redirect unauthenticated users to a login page, etc." (`router_block_view.dart:487-493, 602-608`).
- How it opens in Circuit: `openBlockInCircuit` shows a floating panel, 800x600, centered, named after the argument (`redirect`): `packages/core/lib/src/fields/basic_fields.dart:520-530`. The top node of a closure lists **Return Type** and **Params** (`context`, `state`): `packages/code/lib/src/panels/circuit_details.dart:73-85`. Params appear under **LOCALS** (`FuncExpr.scopeDeclarations` returns the params, `block_tree.dart:6614`, `suggestion.dart:588-605`).
- Adding steps: **Add If statement** (starts with Condition `true`) and **Add Return** (`packages/code/lib/src/widgets/add_statement_menu.dart:60-76`). **Add Return** uses the closure's return type, `FutureOr<String?>` inner `String?` (`add_statement_menu.dart:33-43`; the closure type is inferred from the call argument: `block_tree.dart:6050-6057`, `FuncExpr.inferType` `:6433-6455`), and `defaultBlockForType` gives `''` for String (`block_utils.dart:91-92`). So the new Return starts as empty text, which is why the step says to set **Return** to the login path (an empty string would not be a valid redirect). The trailing `return null` from the default function stays below the If.
- Condition link menu: the If's **Condition** field has the circuit categories because its parent is a `BlockStatement` (`field_link_menu.dart:341`, `block_tree.dart:878, 1725`): libraries (as `SUPABASE_FLUTTER` etc.), **LOCALS**, **GLOBALS**, extra categories such as **FIREBASE** (`suggestion.dart:475-508`; names shown upper-case: `link_menu.dart:331`; library name = file name of the uri, `library.dart:43`). **Custom Expression...** is always the first extra item (`field_link_menu.dart:352-353`) and opens the free-text mode with **Eval** or Enter (`field_link_menu.dart:281-285`, `expression_builder_popup.dart:240-262`, `expression_builder_provider.dart:195-215`).
- go_router semantics (go_router-17.1.0 source comments): route-level `redirect` is "for a specific route (or sub-route)" and "can also be used for conditionally preventing users from visiting routes, also known as route guards. One canonical example is user authentication" (`lib/src/route.dart:167-221`); the top-level `redirect` "runs once per navigation cycle before any route-level redirects" (`lib/src/router.dart:75-87`); a redirect that returns the current location is ignored (`lib/src/configuration.dart:493-503`, `topLocation != prevLocation`). That is why the page recommends a route's own **Redirect Logic** over the app-wide one (which runs for every route, including the login screen). The page does not say a route's logic "runs only when that route opens": a parent route's redirect also applies to routes nested in it (`route.dart:189-210`), so the page just says to add the same logic to every other screen that needs sign-in.
- Default first screen of a new project: `initialLocation: '/home-page'` (`packages/core/lib/src/file_system/templates/common/router_template.dart:17-27`). **Make home screen** sets the initial location: `route_details.dart:262-295`, `go_router_routing_service.dart:13-28` (designer-core research "Make home screen").

**"Is someone signed in?" in a project.**
- Firebase: `FirebaseService.isUserSignedIn()` returns `FirebaseAuth.instance.currentUser != null`; `currentUser` is the getter `FirebaseAuth.instance.currentUser`; both are added when **Authentication** is turned on: `packages/data/lib/src/firebase/auth/fb_auth_blocks.dart:55-99`, `fb_auth_manager.dart:34-42`. They are listed in the **FIREBASE** circuit category (`packages/data/lib/src/firebase/firebase_plugin.dart:121-146`, registered in `firebase_manager.dart:68, 113`). In Play `isUserSignedIn()` returns false and `currentUser` a placeholder user (`fb_auth_blocks.dart:72-76, 95-98`; page `firebase/auth.md` "Test sign-in in Nowa").
- Supabase: GAP. The generated `SupabaseService` has only `initialize`, `signIn`, `signUp`, `signOut` (`packages/data/lib/src/supabase/supabase_manager.dart:214-239`). No getter, no helper in the query templates (`packages/data/lib/src/supabase/templates/*` have nothing for session or user). The Supabase panel's own "Testing as" line reads the editor's session (`packages/data/lib/src/supabase/ui/sb_outline.dart:84-96`), not something the app can call.
- What works instead: the supabase_flutter library is bound in the interpreter, and it is loaded when the package is in the project (registered on connect, `supabase_manager.dart:195`; `packages/core/lib/src/interpreter/packages/dart_package.dart:135-146`). Bound members: `Supabase.instance` and `Supabase.client` (`packages/core/lib/src/interpreter/libraries/supabase_flutter_library.dart:9265-9347`), `SupabaseClient.auth` (`:8486-8491`), `GoTrueClient.currentUser` and `.currentSession` (`:2250-2267`), `Session.user`/`isExpired` (`:3825-3925`), `User.email` and `id` (`:3926-`). The page therefore uses a **Custom Expression** `Supabase.instance.client.auth.currentSession != null`. NOT RUN in the app: I could not try that Eval, and I did not confirm that the name `Supabase` resolves in the router file's scope or that the import is added to `lib/globals/router.dart` (imports are regenerated from references: `block_tree.dart:6860-6885`). **Verifier: please try it.** If it fails, the fallback is the AI tip (a function added to `SupabaseService`; the Supabase panel lists added `.auth.s…` functions only, so a getter would not show there but would show in the circuit category).
- Not a visual building block: no ready-made "signed in" node exists for Supabase, and Nowa does not wrap it. Logged as a gap for product (a generated `isSignedIn` in `SupabaseService` would match Firebase).

**Does the session survive an app restart?** Yes by library default, and Nowa initializes both in the default way:
- `main()` is generated as `WidgetsFlutterBinding.ensureInitialized(); sharedPrefs = ...; <setup statements>; runApp(const MyApp());` (`packages/core/lib/src/project/env_services/main_func_block.dart:15-25`; template `packages/core/lib/src/file_system/templates/common/main_dart_template.dart:28-33`). Statements: Supabase `await SupabaseService().initialize();` (`supabase_manager.dart:188-192`) which calls `Supabase.initialize(url: AppConstants.supabaseUrl, anonKey: AppConstants.supabaseAnonKey)` with no `authOptions` (`supabase_manager.dart:214-226`); Firebase `await Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform);` (`firebase_package_config.dart:13-18`). No `setPersistence`, `EmptyLocalStorage` or `authOptions` anywhere in Nowa's generated code (grep over `packages/data/lib`, `packages/core/lib/src/file_system`, `/project`, `/integrations`).
- supabase_flutter 2.12.0: default `localStorage` is `SharedPreferencesLocalStorage` (browser localStorage on web), `EmptyLocalStorage` is "used to disable persistence" (`lib/src/supabase.dart:111-146`, `lib/src/local_storage.dart:16-110`); `SupabaseAuth.initialize` loads the saved session with `setInitialSession` before `Supabase.initialize` returns, and every session change is saved (`lib/src/supabase_auth.dart:30-75, 125-136`); gotrue `currentSession` returns that session (`gotrue-2.18.0/lib/src/gotrue_client.dart:141-145, 996-1006`). Edge: the restored session may be expired; `recoverSession()` runs afterwards without being awaited (`supabase.dart:138-143`). The page claims only "restore it when the app starts".
- firebase_auth 6.1.4: web default persistence list is IndexedDB, then local storage, then session (`firebase_auth_web-6.1.2/lib/src/interop/auth.dart:22-38`) and `Firebase.initializeApp` waits for the initial auth state (`lib/firebase_auth_web.dart:60-85`, `onWaitInitState`); on phones persistence is not configurable ("Setting a persistence type is only available on web based platforms", `firebase_auth_platform_interface-8.1.6/lib/src/types.dart:30-34`) and the plugin receives the current user at startup (`method_channel_firebase_auth.dart:210-218`, `setInitialValues`). The native SDKs' own storage is not in these sources, and `firebase.google.com` / `supabase.com` docs are blocked here (egress proxy), so the "saved on the device" wording rests on these library sources.

Whether Play runs a route's redirect is NOT claimed (the interpreted router is built from the project's own `appRouter`, `packages/core/lib/src/interpreter/declaration_info/widget_info.dart:120-140`, so it probably does, but I did not run it).
