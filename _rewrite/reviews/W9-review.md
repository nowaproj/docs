## Open issues

1. **Record patterns in `switch` (not documented either way).** `ReferenceBlock.directRun` returns `run(scope).value` (`packages/core/lib/src/interpreter/block_tree.dart:3622`), which for a `RecordObject` is a `Map` (`block_object.dart:195`); `RecordPattern.match` then looks up `$1`, `$2` on that map (`block_tree.dart:5071-5084`) and treats a miss as "no match". So `switch (pair) { (1, _) => ... }` on a record variable probably falls to the default case, as the dev doc says. The released test only covers a record literal as the subject (`dart_loading_test.dart:99-103`), while What's New 3.12.3 says records are matched. I did not run it, so the page claims neither. Needs a runtime check before it is documented as a limitation.
2. **`docs/account/project-settings.md` (not in this batch)** repeats the **load packages** helper text ("loads the packages from your `pubspec.yaml` automatically ... slower to open"). In code the switch is read only by the AI package tools (`packages/ai/lib/src/tools/packages_tool.dart:137`, `legacy/packages_tools.dart:94`); loading at project open is not gated (`packages/core/lib/src/providers/project_provider.dart:228,243-256`). `packages.md` words it as "lets Nowa AI add and remove packages". The account page should match.
3. **Possible product issue, not run.** A top-level function, enum or variable that fails to load is only recorded in `unit.loadFailures`; `BlockUnit.source` rebuilds from the loaded declarations only (`block_tree.dart:6851-6858`), so such a declaration may be dropped when Nowa rewrites that file after a visual edit. The pages say only "skipped and reported".
4. **The repo doc `docs/interpreter_limitations.md` on master is stale** against the 3.12.5 code in two places: barrels (see fix 1) and "object patterns" under destructuring (they work, `ast_to_block_visitor.dart:809-850`). The pages follow the code.
