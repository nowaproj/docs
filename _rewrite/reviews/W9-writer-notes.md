Assumptions / open questions / possible product issues
1. "New projects start with the five default packages" rests on the default pubspec template; projects made from a template or starter may differ.
2. **Helper-text mismatch (affects another page).** The **load packages** switch says "Load packages from pubspec.yaml file automatically ... this will increase loading times", but in code `loadPackagesExperimental` is read only by the AI packages tools (`packages/ai/lib/src/tools/packages_tool.dart:137`, `packages/ai/lib/src/tools/legacy/packages_tools.dart:94`), the dialog and the settings service; loading packages at project open is not gated (`packages/core/lib/src/providers/project_provider.dart:227-255`). `docs/account/project-settings.md` (Experimental flags table) repeats the helper text; it should say the switch lets Nowa AI add and remove packages. This page words it that way.
3. Possible product bug: after **Cancel** in **Add Missing Dependencies**, `_handleDependencies` throws (`packages/core/lib/src/interpreter/packages/package_service.dart:270-272`) and `PackagesTable` has no try/catch (`packages/core/lib/src/settings/packages/packages_settings.dart:107-114`), so "Loading packages..." probably keeps spinning until the page is rebuilt. Not documented.
4. Possible product bug, documented as a note: **Fix** on "'x' is imported but is not in the pubspec." for a Git/path dependency writes the pub.dev version over the entry (`packages/core/lib/src/interpreter/packages/package_service.dart:126-131,208-225`).
5. For cloud projects the package analyzer is called with the version minus `^` (`packages/core/lib/src/interpreter/packages/package_resolver_service.dart:30`), so a range typed in the version field may not load on the board. Not documented (cannot confirm the failure).
